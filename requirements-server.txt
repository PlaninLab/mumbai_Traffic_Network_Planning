# Mumbai Traffic Network Planning — dependencies for the DEPLOYED containers.
#
# The server runs exactly two commands:
#   uvicorn src.web.app:app          (dashboard, report, JSON API)
#   python -m src.data.collect_day   (the metered collection loop)
#
# This file is requirements.txt minus what neither of them imports. Keep it that
# way: every package below is imported by something under src/, so the modelling
# commands (calibration, scenarios, report) still run on the server if needed.
#
# WHY IT IS SEPARATE. The build host reaches PyPI at roughly 200 kB/s, and both
# compose services build the same image at the same time, so every megabyte in
# this file is paid for twice and slowly. Removing JupyterLab (61 distributions)
# and folium/mapclassify (which drags in scikit-learn) takes about 175 MB of
# installed weight out of the image without changing what the containers can do.
#
# requirements.txt stays the DEVELOPMENT set — it keeps JupyterLab and the
# interactive-map extras for notebook work. Add a package to BOTH files when the
# server needs it.

# --- Network construction & graph operations ---

# scikit-learn is NOT optional here, despite being an "optional dependency" of
# osmnx. corridor.graphml is unprojected (epsg:4326), and for an unprojected
# graph ox.nearest_nodes takes the haversine BallTree branch, which is
# scikit-learn. Without it every sweep dies in weh_spine_points() with
# "scikit-learn must be installed as an optional dependency to search an
# unprojected graph". It arrived by accident before, as a dependency of
# mapclassify; that is too fragile to rely on, so it is named here.
